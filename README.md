# 史稿 | 历史小说工作台

个人本地创作工具。史料、写作规划和正文保存在本机；接入模型前先审阅人物关系与情节方案。

## 本地运行

要求 Node.js 20.9 或更新版本。

```sh
npm install
cp .env.example .env.local
npm run dev
```

打开 http://127.0.0.1:3000 。本地 API Key 只由服务端读取，禁止添加 `NEXT_PUBLIC_` 前缀。

## 百炼模型

- `qwen3.8-max`：写作规格、大纲与章节正文。
- `qwen3.8-flash`：史料结构化提取、关联辅助与规则审阅。
- 北京地域兼容端点：`https://dashscope.aliyuncs.com/compatible-mode/v1`。

在 `.env.local` 配置 `DASHSCOPE_API_KEY`。实际价格和账号可用性以百炼控制台为准，文档价格为查询日快照。未配置 Key 时应用不调用外部服务。

## MOBI 参考小说与全文试运行

网页“作品资料”现支持未加密 MOBI（仅参考小说类别，最多 32 MB）。转换在本机进行，保留原始 MOBI、纯文本及来源/正文 SHA-256、目录链接检查清单。不会执行电子书脚本或获取远程资源；加密、损坏及无文本文件明确拒绝。转换目录为 `data/local/converted/<sha256>/`，不进入 Git。

先安装一次转换依赖（Python 3.11 或以上）：

```sh
python3 -m venv data/local/tools/mobi-venv
data/local/tools/mobi-venv/bin/python -m pip install -r scripts/requirements-mobi.txt

```

### 章节中断与继续生成

网页生成接口返回 HTTP 202 后在本地服务后台接收模型流，正文分段写入 SQLite，每次请求另存正文快照和用量。页面自动读取进度；刷新或关闭浏览器不取消后台任务，重新打开可查看已保存正文。任务运行时不能并发生成或保存新版规划。

模型长时间无输出、输出截断或连接断开时保留最后检查点，不自动重发。服务进程中断后，超过 150 秒没有心跳的任务会在读取状态时归档为中断。核对供应商请求与用量后，可手动从已保存末尾继续；续写是携带旧稿的新请求，不是恢复供应商原连接。旧版失败记录若保存了 0 字符，只能重新请求，无法找回未收到的正文。进程被强制终止时，最后尚未落库的小段文本仍可能丢失。

只有明确在长度上限处截断且确有新增正文时才自动续写，单章同一轮最多两次；每段是独立请求与独立快照，续写只接在已保存正文之后。续写开头与已有正文重复时回滚该段并交回人工；断线、超时、无进展或达到上限一律停在未完成状态并保留检查点，人工续写会把计数重置。每次请求仍只受自己的输出上限约束，历史预留与旧稿输入不再被拿去比对整书额度，也不会因此自动加预算或切换计费模式。

`node scripts/test-chapter-stream.mjs` 在临时数据库与独立服务中注入假模型流，验证 202、断线检查点、服务重启、失活锁归档、显式续写、逐章自动续写与重复回滚、接受后的故事状态传递以及前文改写导致的下游待复核；不使用真实 Key、不连接模型供应商。

## 本机古籍固定、史料人物索引与确认后自动生成（2026-11-15）

已采集的 25 部 / 3,563 卷维基文库原文要先入库并固定到项目，才能作为史料证据的唯一来源；四条命令均在离线状态下执行，不产生模型调用：

```sh
npm run corpus:index            # data/local/corpus/wikisource -> corpus_book/corpus_volume（可重复执行，按哈希跳过）
npm run corpus:persons          # 逐卷抽取人名与同段共现 -> corpus_person/corpus_person_edge（零 Token）
npm run corpus:years            # 逐卷解析年纪与干支 -> corpus_entry/corpus_entry_person/corpus_person_profile（零 Token）
npm run refs:register           # 登记已转换的参考小说卷与抽象写作规格 -> reference_novel/reference_spec
```

`corpus:persons` 支持 `--book <id>`、`--min-mentions`、`--max-persons`、`--max-edges` 做单书或阈值调整；`corpus:years` 支持 `--resume` 跳过已解析卷、`--limit <n>` 只跑前 n 卷、`--stats` 只看进度；重建前先 `npm run corpus:check` 确认采集报告完整。`refs:register` 只登记哈希与写作规格文本，参考小说原文永不进入生成上下文。

`corpus:years` 产出两份只读索引：`corpus_entry`／`corpus_entry_person` 是带天文纪年的记事条目（首期只索引《资治通鉴》），`corpus_person_profile` 是从记事里锚定出的生卒与活动年份、年份跨度与主要事迹。年纪标题（「元年春王正月」「二年，汴人大饥」）与干支在句读段内定年、并沿用最近年纪，卷内解析不出年纪的段（如「太祖武皇帝下」）保留卷首纪年；记事中「某某卒／殁／死／诛／及于难／殒于位」视为卒年锚点，「年若干」反推生年，「弱冠／三十许」只给活动年份。同名异人在首期不做消歧，年份跨度超过 90 年或只有单次提及的档案标记为不可信、不进确定候选。

网页流程：资料步骤把本机古籍全集与《冰与火之歌》各自固定到当前项目（取消固定需重新点击），人物步骤的「区域」是可选项、留空即不限区域，候选人物只列出年份档案与所选区间有交集者（区间内出生、去世或活动过即入选），每张卡片展示生卒／活动年份、年份来源与最多三条带卷次出处的主要事迹，并可展开「年份待核」组与「全部史料人物」名单；保存范围只做本机查询、不发起任何生成。事件步骤新增历史事件时给出候选事件——按已勾选人物与起止年份从固定古籍里检出的真实记事，填入后仍要作者核对原文并确认才能采用。随后「确认范围与人物并自动生成」按范围、人物、强关联、派生事件、本地骨架大纲的顺序写入并回显逐步结果。自动路径只在项目已保存「同意资料外发」且服务端配置 Key 时才调用 `qwen3.8-max` 覆盖骨架；章节正文仍需逐章人工批准。

史料预处理未完成时界面不会静默回退：人物与事件读取层在 `corpus_state` 缺少 `years` 标记时返回未就绪，候选区显示需要执行的命令；按年代排序只降级为「不排序」，绝不用书目年代代替人物生卒，也不给导入的人物臆造活动年份。

自动化配置在 `src/app/api/projects/[id]/auto`，最近一次运行保存在 `auto_runs`，可重复执行且幂等：同名人物、已有关系、已采用事件与内容相同的骨架都不会新增规划版本或撤销既有人工确认。

真实 Key 风险提示：`next dev` 会自动加载 `.env`/`.env.local` 的 `DASHSCOPE_API_KEY`，一旦项目保存了“同意资料外发”，模型分支就会真的计费。回归脚本（`npm run test:auto`，即 `node scripts/test-corpus-auto.mjs`）必须在 `HISTORY_DATA_DIR` 隔离目录、`outlineMode=local` 且未同意外发的项目上运行，缺少 `HISTORY_DATA_DIR` 会直接退出，并在断言中检查提示词不含参考小说原文。

## 故事状态、前文变更与待复核（2026-11-17）

章节被人工接受时，本章收束后的摘要、人物所在地、关系口径、各视角已知信息与未收束伏笔固化为该方案版本的“故事状态”（`chapter_states`），同时记录接受时的正文输入版本与当时生效的写作规格版本。下一章请求只带入位于其前且仍为已确认的状态条目：请求体里 `confirmedStoryState.usedInputs` 逐条写明用了哪一章的哪个输入版本，`excludedStoryState` 写明哪些内容因前文变更被排除及原因，界面在章节工作台的故事状态卡同样分“带入本章”和“本章状态”两栏显示，未来章与已失效内容不会静默混入。

改写或删除任一前章正文、重新接受前章，都会让本章状态转为“已失效”，并把其后所有章节标记为“前文变更待复核”——包括当时正在生成的那一章。已写文本一律保留，不自动重写或删除；待复核的章节复核后可以直接重新接受而无需重写正文，重新接受即完成本章复核，但其后章节仍需逐章复核。前一章未接受、正在待复核或没有已确认故事状态时，本章生成请求被拒绝。未完成（截断、断线、达到自动续写上限）的章节不能直接接受，只能先人工续写补全，避免半句截断的正文成为后续章节的既定事实。

## 章节多选队列与章纲改版保留（2026-11-17）

章节工作台的「目录」视图每章标题前增加多选框，可逐章勾选或「全选可入队」，选中项按目录顺序组成一条前端队列。「批量生成并自动接受」只做交互编排：逐章串行调用既有的单章生成与人工接受接口，一章请求落定后才发下一章，绝不并发第二章，也不改动生成逻辑本身。已接受的章节直接跳过、不重发请求；草稿完整即自动接受并固化故事状态；草稿不完整、状态未知、读取不到本章状态或等待超时都让队列停下并说明原因，不跳过也不自动重发。「停止队列」只停止后续调度，已在后台进行的本次请求仍由服务端把正文写到最后一条检查点。正在生成或已中断的章节不入队，仍走各自的单章恢复入口；队列进行中禁用增删排序、保存目录、AI 续设下一章、改写与接受等操作，避免与队列争抢同一版本链。

章纲改版不再重置已确认的章节。保存新版章纲（包括「AI 续设下一章」后保存目录、本地骨架与模型大纲）时，`commitPlan` 在同一事务内把旧版本的已接受正文与待审阅草稿按章节 ID 继承到新版本：本章章纲设定未变且其前序章节同样完整继承时，已接受状态与已固化故事状态原样沿用；否则保留正文、标记「前文变更待复核」并把本章故事状态转为已失效，交由作者复核后重新接受，不重写也不删除任何文本。方案级人工确认仍随新版本撤销（不放宽既有确认口径），队列与章节工作台据此提供「就地确认方案与资料外发」一键补做。生成中与被判定为中断/状态未知的章节不随改版继承草稿，其请求记录、预留费用与已保存正文仍留在旧版本行内可核对；这类章节在新版本里显示为未生成，需要人工核对用量后重新请求。

## 剧情调整后的重新生成（2026-11-18）

剧情提案、已采用史实或范围调整后，已保存章纲会失去有效绑定，逐章生成在此之前被整块拦下、没有任何重新生成入口。现在章纲步骤区分两类拦截：范围、证据与写作规格类仍必须先补齐；提案类保留操作区，直接给出「去剧情提案步骤重新选定」与「到章节工作台按章重生成」两条入口，并在已有章纲时把生成按钮改为「重新生成整本章纲」，同时说明新版会按章节继承已接受正文、章纲有改动的章节转为待复核。

重新生成分两类，都支持全部重生成与自行多选指定章节重生成，且都严格一次调用处理一章。章纲设定重生成只重写所选章节的时间、情节节点、史料编号与章末钩子，其余章节原样保留，结果先进入待保存草稿，逐章审阅后由「保存章节目录」产生新版本；同一轮连续重写相邻章节时，界面上刚生成的邻章设定会随请求带上，钩子链因此接在新版而不是已保存的旧版上。章节正文重生成覆盖本章已有正文，覆盖前旧正文自动归档进 `chapter_draft_backups`，可在章节卡片里查看并「恢复为当前正文」——恢复动作同样先归档当前正文，所以覆盖与恢复来回切换任何一次都不会静默丢字；重生成是整体重写而不是接在旧文末尾续写，默认不自动接受，且本章之后的章节转为待复核，因此必须自前往后逐章推进，未勾选自动接受时队列在完成一章后停下等待人工审阅。生成中、已中断与还没有正文的章节不被覆盖，各走自己的恢复或生成入口。

验证：`npx tsc --noEmit`、`npm run lint` 与 `HISTORY_TEST_BUILD=1 npm run build` 通过；新增 `npm run test:regen`（`scripts/test-regenerate.mjs`）在临时隔离目录与假模型流下断言未确认覆盖 400 且零请求、已有草稿的普通生成仍 409、覆盖后正文不含旧文、旧正文可恢复、下游转待复核、章纲重生成一次一章且带前后章设定、提案过期时两类重新生成均被拦下、保存新版后正文逐章继承，全程零真实模型调用。

## 范围与史料只查询、候选人物与候选事件（2026-11-18）

「范围与史料」步骤的区域字段改为选填：留空即不限区域，只按年份区间筛选，保存后界面记着「不限区域」而不是回落到某个默认值。保存范围只做本机数据查询——写入范围并回显固定书目、时间阶段重叠的书、按年份筛出的候选人物，全程不发起模型请求，也不再自动导入人物。

候选人物改为「生活在所选区间内」的人。新增的 `npm run corpus:years`（零 Token）从固定古籍正文里解析年纪标题与干支，把《资治通鉴》切成带公元年份的记事条目，并为每个人锚定生卒与活动年份、年份跨度与主要事迹。候选只列年份档案与区间有交集者（区间内出生、去世或活动过即入选），卡片展示生卒年份、活动年份、提及次数与最多三条事迹（含年份与原书卷次，可「查原文」），标注年份来源。同名异人尚未消歧，跨度超过 90 年或提及过少的档案判为不可信，单列「年份待核」组、不默认勾选、不进入强关联；年份可信但整个人落在区间外的（如 904—960 的项目里的郭子儀、王世充）既不进候选也不进待核，整体排除。自动导入人物时活动年份只取可信的年份档案，没有档案就留空交人工补填，不用书目年代或作品年份代填。预处理未执行时页面给出需要跑的命令，不再静默回退。

「时间／事件」步骤新增历史事件时提供候选事件：按已勾选人物与填写的起止年份，从固定的《资治通鉴》里检出的真实记事，逐条给出年份、书名卷次、命中人物与原文。选中一条即把年份、原文证据、出处资料与在场人物一并填入表单，仍沿用既有门禁——作者必须核对原文并勾选确认才能采用，出处与证据都要在固定原文里命中。已采用的记事用来源标记去重，不会再作为候选出现；检索区间超出已定年史料覆盖时明确提示区间之外请手工新增。

## 章数放开、章纲分组生成与正文左侧目录（2026-11-18）

人物与事件步骤的每一处多选清单都有了整表入口。已选人物列表给「全选／清空」，候选人物与「年份待核」组各给「全选区间内 N 位／全选待核 N 位／清空选择」，候选事件与待核对的已存事件各给「全部标记已核对／清空」，新增或编辑事件时弹窗里的参与人物也给「全选／清空」（只补到服务端单条 12 位的上限，不做必然被拒的提交）。批量勾选不绕门禁：全选一次提交、服务端逐条按当前范围校验，与范围不匹配或不属于本作品的人物原样跳过并在界面上说明，一次批量只产生一个版本变化；取消勾选不需要匹配当前范围，范围改了仍能把已勾选项收回来。「全选」只代劳打勾这一动作——候选事件仍要逐条核对原文才能采用，候选人物仍要人工导入并核对证据。

章纲的计划章数不再限制在 1–24 或 50 章以内，放开到 1–1000（超出即拒绝并说明原因），模型整本大纲改为「一次调用最多 10 章」的分组串行生成：预览先零请求回显「N 章分 K 次调用」与按组折算的合计输入、输出上限和用量口径；生成时界面逐组推进，进度行写着「第 x / y 组 · 已生成 a / N 章 · 已调用 k 次」，每组请求都带着全书计划、此前已生成章数、上一组末章的章末钩子与第一组的整本设定（书名等以第一组为准），合并后按全书位置重排 `chapter-NN` 编号。凑满计划章数或你显式停笔成稿之前，界面积累的只是草稿，数据库里那一版章纲纹丝不动；某组上游失败或你点「停止并成稿」，已生成的章节都留在界面上，可以继续本组、以已生成章数成稿，或放弃这一批。用量按每次调用回显、由界面累加，方便对着百炼控制台核。章节正文与「按章重新生成章纲」仍是严格一次调用一章，这次放宽只针对整本章纲。
