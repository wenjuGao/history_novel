# 历史小说创作工具需求规格

版本：0.4 | 日期：2026-11-16 | 状态：作品流程已修订，待实施

本文件描述产品行为与验收标准；实施步骤和进度见 [plan.md](plan.md)。

## 1. 范围基线

### 1.1 产品目标

面向个人作者，在本机管理历史资料、参考小说与创作内容，通过商业模型 API 辅助创作连贯的新小说。历史决定主要事实骨架；参考小说仅指导抽象语言特征和情节设计方法；对白、心理、日常场景以及新增人物、人物关系允许虚构，但必须与史实分层管理。

需求来源：本次对话已确认的业务规则、竞品官方资料及阿里云百炼官方说明。首期创作链与路由详见[作品流程设计](plans/2026-11-16-route-isolation-frontend-design.md)；文末日期条目为历史决策记录，与正文冲突时以本版条款为准。

### 1.2 已确认要求

- 个人本地工具，首期不提供多用户协作或公网服务。
- 用户选择单年或年份区间，可选区域。系统按所选史料的活动证据提供人物与事件候选，作者核对并采用。
- 在用户选择或增删人物时检查当前所选人物的关联；修改时间段或区域后重新检查。未找到关联时提示用户，不直接认定历史上没有关联。
- 允许虚构对白、心理、日常场景、新人物和人物关系。
- 参考小说可本地导入；首期从已登记规格选用、编辑和确认。用户自行上传的参考小说的自动规格提炼后置；参考原文不进入大纲和正文生成上下文。
- 上传参考小说只用于写法和情节设计方法，不作为历史事实来源，不搬用具体桥段。
- 商业 API 的 Key 通过项目环境变量配置，由服务端读取。
- 商业服务使用阿里云百炼，支持已配置的按量或 Token Plan 模式，不自动切换计费模式。
- 项目默认模型：`qwen3.8-max` 用于写作规格、大纲和章节生成；`qwen3.8-flash` 用于历史资料结构化提取、关联辅助和规则审阅。用途按能力与成本分配，二者可在服务端配置中调整，但只允许百炼文本模型目录中的有效 Model ID。
- 项目自行抓取默认历史资料，包含完整二十四史及《资治通鉴》；《史记》属于二十四史，默认书目合计 25 部。
- 作者依次核对人物关系、采用历史事件、选择剧情方案，再确认可编辑章纲；按章生成，接受当前章后才推进。
- 首期采用固定工作流，不引入 LangGraph、自由多 Agent 调度、Skill 执行平台或模型微调。

### 1.3 建议默认值与非阻塞决策

以下不是额外获得的用户承诺；实施时可在不削弱已确认要求的前提下调整，并更新本文。

| 事项 | 建议默认值 | 调整条件 |
|---|---|---|
| 历史来源 | 项目抓取已确认默认书目；具体站点、版本和授权逐一核查，保留用户补充导入 | 优先合法开放的原文、官方 API 或允许的批量下载，不抓现代受限整理本 |
| 历史覆盖 | 默认 25 部书目固定；分别展示原文采集、索引、事实提取和人工核定进度 | 资料全集存在不等于任意区域和人物已被完整结构化 |
| 虚构冲突 | 允许填补史料空白，不默认改变已确认的重大事件、人物结局 | 改写重大历史需单独扩展架空模式，不在首版 |
| 模型与计费 | 全局百炼配置；Max 为写作主模型，Flash 为辅助模型 | 按量可估算费用；Token Plan 展示 Token 用量，不换算人民币或 Credits |
| 导入格式 | UTF-8 TXT、Markdown、参考小说用未加密 MOBI，沿用 32 MB 限制 | 文本 PDF、结构化资料包、EPUB 等后续按需增加 |
| 工作量 | 一个运行中的模型任务；作品规模目标 100 章、每章目标约 2,000 至 5,000 中文字 | 属于管理和验证目标，不保证模型单次精确字数 |
| 备份 | 手动本地备份与恢复；正文支持 Markdown、TXT 导出 | 自动备份和其他排版格式后续增加 |

### 1.4 不在首版范围

超出默认书目的全网自动搜集、无审核的持续更新、完整古今地理库、精确古历换算、OCR、自动发布、图片生成、联网协作、用户账户体系、移动端独立应用、自训练模型、向量数据库和图数据库。固定书目抓取、手动增量更新和失败续抓属于首版范围。跨作品上传资料库、三列概览、逐作品模型选择、用户自行上传的参考小说自动提炼和多章批量生成后置。

离线可以整理已有资料和阅读编辑正文；调用商业模型需要网络。资料默认留在本地，但参与模型请求的必要内容会发送到供应商。

## 2. 用户场景与验收

所有场景均可使用预置的已确认资料或已确认方案作为起点独立验收，不要求每次重新走完整流程。P1 为首版核心，P2 为交付完整性功能，均纳入任务范围。

### US1 选择历史范围和人物（P1）

价值：让作者先确定故事的历史边界，而不是让模型随意编造人物选项。

1. 给定已选史料，用户选择单年或区间后，只将活动年份有证据支持的人物列为匹配；指定区域时还需活动地证据。可查看匹配原因和出处。
2. 给定某人物仅在该区域出生、但无所选时期活动证据，不得把出生地自动当作活动地；证据不足者单列说明。
3. 给定没有覆盖资料的范围，展示覆盖不足、抓取/提取进度和补充导入入口，不生成伪装成史实的候选列表。

### US2 检查人物关联（P1）

价值：在写作之前识别不相连的人物群组和时间矛盾。

1. 给定有来源的直接关系，结果展示方向、关系类型、有效时间和出处。
2. 给定经中间人物或共同事件形成的关联，展示完整路径及每一步证据，不将其表述为直接交往。
3. 给定未连通人物群组，提示“当前资料未找到关联”，并允许换人、补资料、平行叙事或显式新增虚构联系后继续。
4. 给定生存时间不重叠的人物，阻止把两人的当面相遇作为可通过审核的情节；仍允许分时代平行叙事。
5. 给定用户选择或增删人物，立即触发当前选择的关联检查；变更时间段或区域后重新检查，不继续展示旧范围的结果为有效结论。

### US3 参考写法并建立虚构设定（P1）

价值：学习叙事技巧，同时避免参考作品污染历史事实。

1. 给定已登记参考小说，作者可以查看、编辑和确认视角、叙述距离、节奏、对话密度等抽象规格；验收时核对大纲与正文请求实际使用同一规格版本。
2. 给定新增人物和关系，用户可保存为虚构设定；模型生成的同类内容也必须带虚构标记。
3. 给定文档中存在“忽略规则”等指令，将其作为资料文本，不提升为系统指令。

### US4 预览并确认创作方案（P1）

价值：作者先看清人物关系和情节走向，再投入正文生成费用。

1. 给定所选史料和人物，可核对带出处的历史时间线；采用事件后再选择剧情提案、编辑章纲，能分别查看历史证据及虚构标记。
2. 给定倒叙章节，可分别查看历史发生顺序和读者阅读顺序，调整叙述顺序不得篡改历史日期。
3. 给定未确认、存在阻断冲突或已过期的方案，界面和直接调用生成接口均不能启动正文生成。
4. 给定已确认方案，修改关系、时间、大纲或写作规格后，相关确认失效；旧快照仍可查看，但不能冒用为新版本的确认。

### US5 分章创作、修改与连贯性复核（P1）

价值：维持长篇内容的状态一致，并允许作者改稿。

1. 给定已确认方案，生成下一章时纳入本章依据、前文摘要、相关原文、人物状态和未收束伏笔。
2. 给定输出含人物引用错误、确切年代冲突或不存在的出处，不能自动成为已通过复核的章节。
3. 给定前章被修改，后续依赖它的摘要、状态和章节标记待复核；系统不得无提示继续使用旧上下文。

### US6 管理商业调用与失败恢复（P1）

价值：让付费调用可追踪，避免误重试和费用失控。

1. 给定未配置 Key 或模型配置不兼容，清楚提示配置问题，不调用替代模型或伪造成功结果。
2. 给定同一生成请求重复提交，只创建一个有效本地任务；网络结果不确定时提示用户，不承诺供应商侧绝不重复计费。
3. 给定应用重启，可查看已保存结果和中断节点，显式选择恢复；取消后不再启动新调用。
4. 给定正文方案已确认、作者已同意本次用途的资料外发且模型配置有效，可直接启动指定一章，无须填报整书预算或 Token 上限。
5. 给定无效 Model ID、账号无权限或余额/配额不可用，拒绝调用并提示处理，不静默切换模型；调用前展示使用模型和计费模式；按量显示可用的费用估算。

### US7 本地保存、导出与恢复（P2）

价值：保证资料和作品可携带、可恢复，不被模型服务锁定。

1. 给定已保存的作品，断网后仍可打开、编辑和导出正文。
2. 给定包含资料、来源、确认记录和章节版本的备份，在干净数据目录可恢复等价作品，不包含 Key。
3. 给定扫描件、超限或损坏文件，在解析前后适当阶段明确拒绝，不展示空白的“导入成功”。

### US8 获取默认历史资料（P1）

价值：无需用户自行搜集整套古籍，同时能审查出处和实际覆盖。

1. 给定默认书目，用户可查看 25 部书的来源审核、卷目清单和抓取状态，包含《史记》《资治通鉴》，且《史记》不重复计数。
2. 给定合法来源与已通过核对的版本清单，抓取保存书、卷、篇、段落及 URL/修订号；网络中断后只补缺失或变更项，保留旧版本。
3. 给定站点拒绝抓取、许可不明、验证码、登录墙或限流，任务停止或按规则退避，展示失败原因，不绕过限制或声称书已完整。
4. 给定整套原文已缓存，仅对所选范围相关片段进行有预算的模型提取；未提取和未核定范围有明确标记，不能由原文下载完成直接变成已核实史实库。

### 边界与异常

- 时间支持公元前、公元后、范围和未知值；缺失或大致时间不得伪造为精确日期；跨公元前后不引入历史零年。
- 区域以带别名的可维护条目为准，不承诺完整古今疆域重建；未识别地点等待用户映射。
- 同名人物不得仅凭名称自动合并；跨时代关系必须有有效时间，不能用未来关系证明过去关联。
- 同时代、同区域、同阵营只提供背景关联，不自动证明相识或同场。
- 共同事件需要人物参与证据；模型认为“很可能参加”不能当成事实关联边。
- 缺出处、来源被删除、资料存在分歧时保留提示；事实支持失效不能只删除提示后继续。
- 非线性叙事同时考虑历史时间、叙述进度和视角人物当时已知信息。
- 模型超时、限流、返回截断、结构错误、模型不支持所需能力时，不提交半成品为完成结果。
- 应用关闭或取消后，供应商可能仍处理已发送请求；展示费用与取消能力的限制。

## 3. 需求

每项编号均为独立验收项。表中的“校验”只表示可证明的局部规则，不表示自动保证历史真实性或原创性。

### 3.1 项目与历史资料

| 编号 | 需求及验收条件 |
|---|---|
| REQ-001 | 创建、重命名和打开多个本地创作项目，隔离各项目资料、方案和章节；保存后重启不丢失已提交内容。 |
| REQ-002 | 展示默认古籍及补充资料的来源、覆盖时间、区域、版本与缺口，分别呈现抓取、索引、提取和核定状态；无覆盖范围不得冒充有完整人物库。 |
| REQ-003 | 支持单年或起止年份（无零年历史纪年）及可选区域；拒绝逆序，保留原文纪年与精度。仅可靠定位的时间用于匹配；年代不明独立标记。范围或史料选用变化后刷新候选，原已选但不再匹配的内容标记待复核。 |
| REQ-004 | 从有出处的人物资料提供候选项，展示生卒、身份、活动时间地点、匹配证据；仅证据不足者不得混入确定匹配结果。 |
| REQ-005 | 支持人物别名与区域别名检索；同名异人保持不同身份，合并前展示差异并要求用户确认。 |
| REQ-006 | 导入历史文本，后续可扩展结构化资料包；保留原始文件、标题、版本、权利说明（可填未知）、稳定片段定位；识别重复文件并拒绝损坏、超限或无文本内容。 |
| REQ-007 | 人物、事件、事实和关系的依据可回到实际来源片段；模型提取先进入待核对状态，出处存在校验不等于事实已被核实，支持用户确认或否决。 |
| REQ-008 | 同一事实可保留多种说法与对应出处，用户选择采用口径；存疑、冲突和来源失效均可见且不得静默覆盖。 |
| REQ-052 | 第 9 节的 25 部古籍为默认共享语料，作品明确固定使用的资料版本，并可保留私有上传作为补充。证据校验和候选只使用作品选用且可定位原文的史料；上传但尚未处理的材料标记待补充。共享资料更新不静默替换已有证据。 |

### 3.2 参考小说与写作规格

| 编号 | 需求及验收条件 |
|---|---|
| REQ-009 | 历史资料与参考小说分开导入和分类。首期沿用 TXT、Markdown 和仅供参考小说使用的未加密 MOBI（最多 32 MB）；上传成功与写作规格可用分别展示。 |
| REQ-010 | 从已登记参考小说选用写作规格，按作品预览、编辑并确认版本，覆盖语言、视角、节奏、对话与情节设计方法。大纲及各章实际请求使用同一已确认版本；用户自行上传的参考小说的自动提炼后置。 |
| REQ-011 | 正文上下文不直接检索参考小说原文、人物和具体桥段；风格分析产物经过检查后才可采用，文档内容一律不具有指令权限；提供明显重复表达的辅助提示，但不宣称保证零侵权。 |
| REQ-053 | 本机已登记参考小说可作为默认候选（如已登记的《冰与火之歌》五卷）。记录参考来源、源文本版本及作品已确认规格版本；大纲和正文只使用抽象规格，不携带原作原文、人物或桥段。源文本变化时提示重新登记并确认；旧稿保留原版本。 |

### 3.3 人物关联与虚构管理

| 编号 | 需求及验收条件 |
|---|---|
| REQ-012 | 显示有依据的直接关系，包含关系类型、方向、有效时间、出处及状态；查询时仅采用在相应时间成立的已确认史实边。 |
| REQ-013 | 显示经人物或共同事件形成的间接关联路径，逐步列出处；最多展示 3 条最短可解释路径，背景相似不得冒充相识或实际交往。 |
| REQ-014 | 检查所选人物的连通群组及孤立项；提示“当前资料未找到关联”及资料范围，允许换人、补资料、平行叙事或显式虚构连接，不强制所有人物必须连通。 |
| REQ-015 | 提示人物生存时间、活动时期、关系有效期与事件时间冲突；确证不可能的同场情节阻断方案确认，时间未知则警告而非擅自判定不可能。 |
| REQ-016 | 用户或模型可新增虚构人物、关系、对白、心理及日常场景；新增设定可编辑、删除，且不得覆盖真实人物身份和原始证据。 |
| REQ-017 | 事实断言、人物关系和计划情节明确标记史实、存疑或虚构，确认流程与标记分开；参考小说和生成正文不得自动成为史实来源，虚构连接不计入历史关联检查。 |
| REQ-018 | 默认保持已确认重大历史事件和人物结局；新增虚构设定与已确认事实冲突时显示差异并阻止以当前口径确认，允许修订虚构内容或补充证据后重新核定事实。 |
| REQ-054 | 古籍人名索引用于发现线索。匹配候选须有与所选年份内活动相符的原文证据，并展示出处、原文纪年、精度及匹配理由；仅被提及、时间不明或身份存疑者单列待核。不得以作品年份补齐活动年份；自动记录的同段共现只作为待核线索；未经作者核对原文并确认关系，不进入已核定关系图、历史事件依据或生成上下文。可选择、忽略或恢复候选。 |

### 3.4 情节规划与生成前确认

| 编号 | 需求及验收条件 |
|---|---|
| REQ-019 | 基于已采用史实和选定剧情提案生成可编辑的大纲与章纲。每章列明时间、地点（已知时）、视角、核心冲突、史实依据、虚构边界与章末承接；可约定建议章长。 |

## 5. 状态与审批规则

- 资料提取：待核对、已采用、已否决；与史实/存疑/虚构分类正交。
- 历史事件：待核、已采用、已否决；仅有效的已采用事件进入大纲证据集合。剧情提案另记草稿或已选。
- 方案：草稿、待确认、已确认、已过期。确认不保证史实客观正确，只记录用户采用的依据和方案。
- 章节：未生成、生成中、未完成、完整草稿、已接受、待复核。只有当前有效版本的已接受章节可供默认后续生成使用。
- 任务：排队、运行、等待用户、成功、失败、取消、中断；过期输出作为结果附属状态单独保留。
- 用户对“没有找到关联”的确认不等同于将虚构关系认定为历史关系。
- 恢复必须复核输入版本、费用和结果是否已保存；不能通过重启绕过确认或重复提交旧状态。
- 长任务不持有数据库长事务；阶段结果提交成功后再进入下一步骤。

## 7. 风险与发布条件

- 历史覆盖和人物关联受已抓取并完成提取核定的资料限制；有全集原文也不等于完整人物数据库，空库或未处理范围必须提供诚实状态。
- 来源真实不等于内容正确；冲突史料需要用户选定口径。商业模型只能辅助核对。
- 不使用“模型审阅通过”宣传零幻觉；生成式文字仍需人工审核。
- 旧规划使用位置式证据编号。验收须覆盖增删事件后旧编号的解释仍绑定旧方案，无法追溯的旧引用应标待复核，不猜测其指向。
- 史料人物候选与强关联来自本机启发式索引（词典加动词邻接），会把官职、封号、地名误当人名，也把同一叙事段落内的并列出现当成共现；因此候选默认勾选只表示“值得看”，强关联标签说明口径为同段共现次数与卷数，不等于史载实际交往，噪声由黑名单、不再显示与人工核对消化。
- 自动流程会保存作品候选和版本；回归在 `HISTORY_DATA_DIR` 隔离目录使用本地或模拟调用，禁止访问真实供应商。
- PDF、备份包与模型上下文是不可信输入；参考作品需要用户具有合法使用权限。
- 商业供应商的数据保留、训练使用、地区可用性和价格必须在选型时复核；本机保存不等于全流程离线。
- 正式交付必须实现并执行默认 25 部古籍的合规获取与完整性校验，另从已获取原文建立人工核定的直接/间接/孤立/冲突样例；全量原文获取不要求一次性全量付费提取，也不承诺逐句人工校勘。
- 模型供应商已确定为百炼；发布前核对所选 Model ID、地域和计费模式，用户自行配置 API Key 后进行小额联调；未提供 Key 时不得宣称真实生成已验证。
- API Key 对应区域的网络端点、模型清单和权限彼此关联；任何地域配置变化必须同步校验，不能将其他地域 Key/Base URL 混用。
- 本轮仅修订需求与任务，未执行全集抓取；候选网站暂未验证可访问和可采集，具体授权版本与来源仍需在采集任务中核定。

## 2026-11-18 需求修订：剧情调整后的章纲与正文重新生成

用户提出「剧情提案调整后章纲需要支持重新生成，增加重新生成入口；章纲调整支持章节目录与正文全部重新生成或自行多选指定章节重新生成；章节正文不组合生成，一次调用只生成一个章节」，新增 REQ-060，并逐项确认口径。其一，旧正文处理：覆盖前归档到备份表并可恢复，而不是直接丢弃或另存新草稿——已写过的文本一律可回退，这是既有「不丢字」口径（REQ-026/REQ-059）的延伸；恢复上一版时当前正文同样先归档，因此来回切换任何一次都不静默丢内容。其二，入口位置：章纲步骤与章节工作台两处都要有，且章纲步骤在提案类拦截下不得把重新生成入口一起收起（范围、证据、写作规格类拦截仍必须先补齐）。其三，「按章重新生成章纲」的范围语义是只重写所选章节，其余章节原样不动，不是从所选章起整本重排。其四，正文重生成后默认不自动接受，交由人工审阅。

据此调整的既有条款解释：REQ-027 的「一次请求一章」同样约束重生成路径，正文重生成不得把多章合并成一次调用，也不得把旧正文当作续写前缀；REQ-056 的章纲必须绑定选定提案，因此提案输入哈希变化时重新生成入口只提供路径、不放行请求，须先回到提案步骤重新选定；REQ-058 的队列顺序门禁在重生成下更紧——覆盖本章会让其后章节转待复核，故正文重生成只能自前往后推进，未开自动接受时队列在完成一章后即停下；REQ-026/REQ-029 的故事状态口径不因恢复旧版而回溯，恢复后该章仍需重新接受。生成中、已中断与尚无正文的章节不属于可覆盖对象，各有自己的续写或生成入口。

## 2026-11-18 需求修订：范围与史料只查询、候选人物按年份、候选事件

用户提出两项口径，新增 REQ-061、REQ-062、REQ-063。其一，「范围和史料」中的区域是非必填的；选定起始与结束年份后候选人物名单必须随之改变，且名单只能包含生活在起始与结束年份之间的人，名单中要展示人物主要事迹与生卒日期；人物数据是基于史料生成的预处理数据、需要前置处理；保存历史范围只做数据查询。其二，新增事件时需要提供候选事件，候选事件是基于史料、人物、时间生成的真实事件。

四项已确认口径：人物生卒与活动年份数据用「本地年纪锚点 + 模型补全」两条腿，本次交付锚点、模型补全作为需另行批准的第二批（涉及资料外发与真实计费）；入选判定为「区间有交集即入选」；候选事件首期只覆盖《资治通鉴》；预处理以离线 npm 命令执行、页面显示就绪态。

据此调整的既有条款解释：REQ-003 的区域为空即不限区域，不再是缺失输入；REQ-054 的「人物年份不得臆造」扩展到自动导入路径——没有可信年份档案就不写活动年份；REQ-052 的证据唯一来源口径同时约束候选事件，候选原文必须能在固定古籍里 `instr()` 命中；REQ-055 的「自动内容仍需人工核对原文」延伸到候选事件，候选只预填、采用仍须勾选确认。保存范围由「顺带跑一次自动生成」收窄为纯查询，是 REQ-049 预览—确认口径的进一步收紧。

## 2026-11-18 需求修订：勾选列表全选、章纲分组生成与正文目录侧栏

用户提出三项口径，新增 REQ-064、REQ-065、REQ-066。其一，「人物和事件冲突支持全选」确认作用在人物与事件的勾选列表上——「冲突」在本产品里只是剧情提案的一个文本字段，不是可勾选清单，因此全选落在候选人物、「年份待核」组、已选人物、候选事件核对与事件弹窗的参与人物上。其二，「章节数量不限制，章节 10 个一组在一个调用中生成，超过时候自动分组逐组生成」确认作用在大纲／章纲生成路径，章数口径为「放开数量 + 保留兜底上限」。其三，「正文章节在内容区域左侧固定展示，左侧章节和右侧内容支持独立上下滚动」确认选择 sticky 侧栏形态，不改动项目工作台既有的单一滚动容器。

据此调整的既有条款解释：REQ-049 的预览—确认口径在分组路径下按整本折算（组数 × 每组预算）后回显，预览仍不得发出请求；REQ-055 的自动骨架大纲仍是零 Token 单次写入，本次分组只作用于模型整本生成；REQ-027 与 REQ-060 的「一次调用一章」只约束正文与按章重生成，不因章纲分组而放宽，章纲分组的上限是每次 10 章而不是整本；REQ-003 与 REQ-062 的范围门禁同时约束批量全选，全选不是绕过范围检查的通道；REQ-040 的窄屏无溢出验收同时覆盖新的左侧目录与回退后的横向章节条。

同日复核修订：第三项首版实现做成了「`lg` 以上才出现的 sticky 侧栏 + 正文仍随页面滚动」，用户判定「以上需求未实现」。REQ-066 因此按双栏独立滚动重述，实现口径改为：外层用 `h-full min-h-0` 把项目工作台滚动容器的确定高度传到阅读视图，行容器 `flex min-h-0 flex-1`，目录栏靠交叉轴拉伸取到与正文行等高（不再用 `self-start` + `calc(100dvh-…)` 估算，否则目录比行高出数十像素、把溢出漏回页面），正文栏自身 `overflow-y-auto`；目录栏从 `sm`（640px）起常驻，窄屏章节条用 `hidden … max-sm:flex` 而非 `flex … sm:hidden`——后者在本项目的 Tailwind v4 产物里会被无变体的 `.flex` 覆盖，导致桌面宽度仍渲染出重复的章节条。页面滚动容器在阅读视图的滚动量必须为 0，作为「两栏各自滚动、不带动整页」的验收锚点。
