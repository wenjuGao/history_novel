# 历史小说工作台：作品流程与路由隔离设计

日期：2026-11-16 | 状态：需求修订稿，待实施 | 关联：[需求规格](../spec.md)、[实施计划](../plan.md)

## 1. 目标与首期范围

作者输入单年或年份区间，选定史料与一本已登记的参考小说。系统给出可查出处的人物、关系和历史事件，基于作者采用的史实提出剧情，形成可编辑的章纲。作者确认后，系统按章写作；下一章承接上一章被接受后形成的故事状态。

现有应用是个人本地工作台，页面层只有 `/`；已有作品级 API、按作品重建的 `StoryProvider`、共享古籍与作品引用、写作规格登记、章纲版本、逐章确认和中断恢复。继续使用这些能力与现有技术栈（Next.js App Router、SQLite、better-sqlite3）。首期优先验证从选年份到写完连续两章的流程。允许保留现有作品上传和全局默认模型。跨作品上传库、三列概览、逐作品模型选择和用户自行上传的参考小说的自动规格提炼列为后续项。

## 2. 路由和导航

| 路由 | 职责 |
|---|---|
| `/` | 创建和打开作品，显示最近作品、进度与模型配置入口。 |
| `/models` | 显示全局模型、用途、端点与计费模式、Key 是否配置。Key 由服务端环境读取，明文不回显、不入库。 |
| `/projects/[projectId]` | 进入作品。新作品进入范围设置；已有作品回到其最后一个仍可用的步骤或章节；无法恢复时回到章节目录或首个未完成的前置步骤。 |
| `/projects/[projectId]/setup/scope` | 设置单年或起止年份、可选区域，确认本作品采用的史料。 |
| `/projects/[projectId]/setup/references` | 选择已登记参考小说，预览、编辑和确认其写作规格。 |
| `/projects/[projectId]/setup/persons` | 选择人物、查看关系简述、证据和待核线索。 |
| `/projects/[projectId]/setup/events` | 审阅史料时间线、采用事件，选择或编辑剧情提案。 |
| `/projects/[projectId]/setup/outline` | 编辑和确认大纲、章纲；可填建议章长，留空使用默认值。 |
| `/projects/[projectId]/chapters`、`…/chapters/[chapterId]` | 查看目录与进度，打开指定章节，逐章生成、续写、编辑与确认。 |

作品路由布局校验作品存在，客户端状态以 URL 中的作品 ID 为准，切作品重建作品上下文。章节直达仍校验作品及章节归属；可阅读已有草稿或快照，生成权限由服务端按前置条件重新判断。最近打开记忆只用于导航。作品、资料引用、规划、章节和生成任务的读写按作品作用域校验，同源检查沿用现有机制。此处的隔离针对本机多作品。

## 3. 作品流程

1. **范围与史料。** 单年视为起止同年；区域留空时不按区域筛选。保留原文纪年和精度；可可靠定位的纪年用于匹配，无法可靠定位的保留为待核。首期沿用默认古籍的作品固定及作品私有上传。候选只使用作品明确选用、能够定位证据的史料；只有文件、尚未处理的补充资料可提示补充或手动核定。范围或史料选用变化后刷新人物与事件候选；已选但不再匹配的内容保留并标记待复核。
2. **参考小说与写作规格。** 史料决定事实依据；参考小说只提供视角、叙述距离、节奏、对白和伏笔等抽象方法。上传、登记、规格已就绪和作品已确认是不同状态。首期选择一份已登记规格，允许按作品调整并确认版本；可用预置系列作为默认候选。实际大纲和各章正文请求都携带同一已确认版本，参考小说原文、原作人物和具体桥段不进入这两类请求。更换参考或其源版本变化时提示作者，旧稿保留旧版本，新生成使用重新确认的规格。
3. **人物与关系。** 书目覆盖和人名共现用于发现线索。只有原文能支持相应年份内的活动（指定区域时还需支持活动地）才列入匹配候选；仅被提及、年代不明或身份可疑的人物单列待核。不得把作品年份填作人物活动年份；自动记录的同段共现只作为待核线索；未经作者核对原文确实支持该关系，不得进入已核定关系图、历史事件依据或生成上下文。用户可核对原文、勾选或忽略线索，并查看有证据的直接或间接关系。
4. **历史事件与剧情提案。** 先提供一条由事件候选组成的历史时间线，注明人物、时间或时间精度、出处及分歧，用户核对后采用。引文命中只证明出处存在，待核线索不得自动升级为已采用史实。再基于同一组已采用史实给出剧情提案，可并列展示至多三种视角、主线和冲突，区分固定史实与虚构补写。允许手动编辑或重生成未采用提案；重生成不改已采用的史实和当前选定提案。证据不足时提示补资料或核对线索。
5. **章纲与确认。** 作者基于选定提案生成并编辑章纲，章纲至少包含章节时间、视角、核心冲突、事件证据、虚构边界和章末承接。建议章长为节奏参考。确认绑定历史范围、史料证据版本、人物关系、剧情提案、写作规格和章纲。模型调用前单独校验外发同意。历史口径、写作规格或章纲发生变更后，标记受影响项待复核；保留可读旧稿。新作品缺少有效配置时提示完成前置步骤，不使用旧试跑资料兜底。
6. **逐章写作。** 按确定的章纲只启动当前一章；草稿可编辑，复核通过且用户确认后，留下本章摘要、人物所在与关系变化、视角知识边界和未收束伏笔。下一章使用已确认的累积故事状态、本章证据和同一写作规格。修改已确认前文时，保留原快照，把依赖它的状态与后续章标记待复核，不自动重写。

## 4. 模型调用、完整性与恢复

- 正文不要求作者填写整书预算或 Token 上限；仍需当前方案确认和有效的资料外发同意。展示实际使用的模型、计费模式和请求用量；按量估算与账单区分，Token Plan 不换算为人民币或套餐 Credits。
- 单次请求保留输出限制。只有明确因长度截断且已有有效进展时，才从已保存正文自动续写；同一章的自动续写次数有上限。使用同一输入版本，记录各段边界和用量，拼接时检查重复和缺段。
- 断线、失败、无进展、达到续写上限或用户取消时保留检查点并停止后续请求，标识为未完成。结果未知的请求不自动重发；用户可从最后有效检查点手动继续。仅完整、通过阻断检查的草稿可以确认。

## 5. 数据边界与后续扩展

- 作品配置与产物按作品持久化：范围、资料引用与版本、人物和事件采用状态、规格版本、剧情提案、章纲及确认、正文快照和故事状态。历史证据引用需能定位原文及其版本；展示用编号变动时不得重新指向另一段证据。
- **旧作品兼容。** 原事件、章纲与正文快照原样保留，可回看原引用。缺少可验证的人工确认记录的旧派生事件，在当前流程标为待复核；旧「已采用」状态或「派生」标记不能代替确认。核对原文能否支持事件内容、年代和参与人物，且仍适用当前范围及所选史料后，记录本次确认，才可纳入新规划和正文。当前规划仍依赖待复核证据时，提示先核对或更换依据并重新确认方案，再继续写作。
- 生成记录按作品保存请求意图、所属步骤或章节、输入版本与哈希、幂等标识、结果、检查点、模型和用量。诊断日志保留必要事件与片段边界，不保存 Key；已有按哈希保存的文件可继续由 SQLite 登记清单和路径。
- 后续建设平台上传库时，作品引用具体材料版本；共享资料更新或归档不替换已有证据。首期保持 TXT、Markdown 和未加密 MOBI 的既有上传限制（最多 32 MB，MOBI 仅作参考小说）。全局模型目录保持现有配置，逐作品模型绑定后置。

## 6. 首期验收

- **一条完整创作链。** 选定一个年份和已登记参考小说；核对并采用人物及事件，确认写作规格和章纲，生成并确认第一章，再生成第二章。核对两章实际使用同一规格版本，第二章承接第一章确认后保存的故事状态，可回查历史依据。
- **证据、版本与隔离。** 同一本史书中只在目标年份外出现的人物不能成为确定匹配；年代不明进入待核。改年份或史料后候选更新，旧稿证据仍可追溯。修改风格或前章后，受影响结果待复核。跨作品章节或任务 ID 无法读写，刷新与直达能恢复正确进度。
- **旧作品续写。** 打开含旧派生事件和自动共现关系的作品，旧稿和快照仍可读取。待复核事件和关系不进入新请求；作者核对并确认所需证据、重新确认受影响方案后，可以继续生成下一章。
- **失败与恢复。** 模拟长度截断、重复片段、断线、达到续写上限和取消；均保留有效进度，未完成不进入确认。未同意外发或方案过期时无模型请求。回归使用隔离数据目录和假模型流，不使用真实 Key。
